项目经历

页外 ElsePage · Reading Agent & Personal Knowledge System

Swift / iOS · Agent Runtime · 独立开发

面向传统阅读器难以沉淀长期思考、通用 Chatbot 缺少真实阅读上下文的问题，独立开发 local-first Reading Agent，将书籍原文、阅读位置、批注、历史 Reflection 与长期 Memory 组织为可检索、可追溯、可持续演化的 Agent Context，形成 Read → Reflect → Discuss → Remember → Reconnect 产品闭环；工程包含 13 个模块，356 个自动化测试全绿。

  • Context Engineering：针对固定 Prompt 难以判断本轮需要哪些 Context、而让 LLM 自由检索又难以约束数据范围与成本的问题，设计 Semantic Planning → Validation → Policy Compilation → Context Assembly 分层链路；LLM 负责判断用户意图、Query 与检索范围，确定性代码统一裁决数据可用性、Retrieval Strategy、Context Budget 与回复策略，并提供规则化 Fallback，使上下文选择可测试、可审计、失败可降级。
  • Hybrid RAG：针对整本 EPUB 无法直接放入 Context Window、普通 Top-K 又可能召回未读章节的问题，从零实现 Parent/Child Chunking → BM25 + Vector Retrieval → RRF → Cross-encoder Rerank → Small-to-Big Expansion；以小粒度 Chunk 负责精准召回、大粒度 Chunk 补足上下文，并在检索与扩展阶段持续校验 read-so-far 边界，实现跨章节语义召回的同时从检索层阻断未读内容。
  • Long-term Memory：针对用户的反思、疑问与观点长期散落、普通 Conversation Memory 又容易退化为不可解释的摘要的问题，设计 Thought / Question / Memory 三类长期记忆，并为其建立 Evidence、Relation 与 Revision；每次反思后由 LLM 提出更新建议，再经过规则校验后写入，并保留观点演化的历史版本，使 Agent 的长期记忆具备证据来源、修订能力与持续演化能力。
  • Agent 可靠性与可观测性：针对移动端模型调用可能出现超时、取消、输出截断、Provider 异常和重试重复等问题，自研有界 Agent Runtime，通过调用次数、执行时间、输出长度三重预算及幂等机制控制模型调用；同时建立 Evidence → Generation → Citation → Local Validation 可信链路，并记录 Context Routing、检索、预算、Fallback 与长期记忆更新等关键过程，使 Agent 行为可恢复、可追踪、可定位问题。GitHub 源码
